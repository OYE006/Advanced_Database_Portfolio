# Performance Analysis: Query Processing and Optimisation 

The SecureBank SQL queries have been written to allow relational data to be manipulated using joins, filtering, aggregation and ordering. Indexing has been added to columns that are queried often such as transfer status, source account, destination account and ledger account. The EXPLAIN command was used to determine what query plans were being executed both before and after indexing. I paid particular attention to what indexes were being used, how many rows were estimated to be processed and if there was any ordering that was performed. Due to the small size of the sample dataset, MySQL may decide to perform a table scan as opposed to an index scan. This is because a number of rows can be retrieved directly from the table using less system resources. This means that the benefits of indexing may not be obvious in this case. A larger dataset needs to be used to see the performance improvements. This analysis has shown how having well set out indexes and optimised queries increases the speed of retrieving information from the database. It has also highlighted the importance of checking the query plans.
